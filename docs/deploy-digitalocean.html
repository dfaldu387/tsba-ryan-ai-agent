Base server setup

SSH as root@170.64.199.2
  • Security updates, a non-root tsba user, firewall, 2 GB swap.
  • Install Node 22, git, Nginx, Certbot, Docker, PM2 — then reboot.
  • On “modified config file” prompts choose keep the local version.
apt update && apt upgrade -y

adduser tsba && usermod -aG sudo tsba
rsync -a ~/.ssh /home/tsba/ && chown -R tsba:tsba /home/tsba/.ssh

ufw allow OpenSSH && ufw allow 80,443/tcp && ufw --force enable

fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git nginx certbot python3-certbot-nginx docker.io docker-compose-v2
usermod -aG docker tsba
npm i -g pm2

reboot
# after reboot, log in as the app user and verify
ssh tsba@170.64.199.2
node -v && pm2 -v && docker --version && free -h && sudo ufw status
Expect: Node v22.x · Swap 2.0Gi · ufw active (OpenSSH, 80, 443).

~/app
  • Edit docker-compose.yml: bind to localhost and set a strong password.

Docker bypasses ufw — the default "5432:5432" would expose Postgres (password tsba) to the internet.
# docker-compose.yml changes
    environment:
      POSTGRES_PASSWORD: <strong-password>
    ports:
      - "127.0.0.1:5432:5432"
nano docker-compose.yml
docker compose up -d && docker ps

Nginx reverse proxy + HTTPS

server (sudo)
  • Proxy the domain to 127.0.0.1:8080 with long timeouts (AI answers, scrapes) and 50 MB uploads.
  • Certbot issues the certificate and adds the HTTPS redirect. DNS must already point to the droplet.
# sudo nano /etc/nginx/sites-available/tsba
server {
  server_name console.tsba.au;
  client_max_body_size 50M;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 300s;
    proxy_buffering off;
  }
}
sudo ln -s /etc/nginx/sites-available/tsba /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d console.tsba.au
Open https://console.tsba.au and sign in with the admin account.

Project-specific setup

various
  • Turnstile portals (e.g. Solarman): the server can't solve the challenge. Capture on your PC (npm run portal-chrome → npm run portal-capture), re-upload backend/.portal-sessions/, then pm2 restart tsba.
  • Portal logins (GoodWe SEMS+, WHES, Dyness): the server has no screen, so npm run portal-login <key> only works on your PC. Sign in there, then re-upload backend/.portal-sessions/ and pm2 restart tsba. WHES lives at ecos-hub.whes.com; leave WHES_PORTAL_URL unset.
  • Twilio (sales follow-up SMS): point inbound webhooks at the HTTPS domain, not localhost.
  • Gmail / Drive: reconnect from the admin panel once the redirect URI is updated.
  • Backups: droplet backups + nightly DB dump.
mkdir -p ~/backups && crontab -e
# add this line:
0 2 * * * docker exec tsba-db pg_dump -U tsba tsba | gzip > ~/backups/tsba-$(date +\%F).sql.gz

Quick troubleshooting

server
  • 502 Bad Gateway → app is down: pm2 logs tsba (often a missing env var or DB not running).
  • “Missing required env var” → fix ~/app/.env, then pm2 restart tsba.
  • Scraper “session expired” → recapture sessions on your PC (step 8).
  • Chromium fails to launch → re-run the playwright install --with-deps chromium line.
  • Out of memory → check free -h; lower SCRAPER_MAX_CONTEXTS in .env or resize the droplet.
  • Certbot fails → DNS not pointing yet: dig +short console.tsba.au must return 170.64.199.2.
