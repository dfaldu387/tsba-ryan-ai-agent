Ready for
production

The support system works: a browser crawl found no broken page, console error or failed request, and no data was lost. Before these fixes it was not safe to leave unattended: an approved reply could be emailed to a customer twice, alert emails produced false "recovered" and repeat mails, and a fresh install was broken. Every confirmed issue is now fixed and tested locally, so the support system is ready for production once these fixes are deployed. The improvements listed under Pending are optional. AOverall system health

Assessment

Functionally complete and stable in normal use. The weak spots were background jobs that email customers and admins, and security controls that only existed in the browser.

Stability

No crashes or console errors on any support page, at desktop and phone width. Background jobs (alert monitor, snapshot recorder, embedding queue) now guard against overlap, survive restarts and shut down cleanly.

Production readiness

Ready once these fixes are deployed and npm run migrate is run. Lint, typecheck, unit tests, builds and the migration all pass locally.

Major risks (before fixes)

Duplicate customer replies, the knowledge base being wiped by a failed Drive re-sync, unlimited password guessing, and viewer accounts able to read customer contact details from the API.

CFixes implemented

Frontend

  • Error state with retry instead of "No plants" when the first load fails; newest fleet request always wins.
  • Drawer keeps typing focus; drafts deep link applied once; alert-row keyboard and recipient fixes.
  • Globe tooltip escaped and masked for viewers; wrong-password and too-many-attempts messages.
  • Opening download 25% smaller (446 → 336 kB) by loading rarely used pages on demand; no source maps in production.

Backend

  • Drafts: approve/reject only while pending (repeat returns 409).
  • Resync checks every folder before deleting anything; one run at a time.
  • Alert monitor clears only checked plants, persists state across restarts, shares the overlap guard.
  • Cache sweep, idle-browser fix, local "today" date, graceful shutdown, queue start/batch fixes.
  • Internal errors are logged in full and users get a plain message; validation messages still show as written.

Database

  • schema.sql now includes the hand-run migration's columns.
  • npm run migrate runs migrations and records them in schema_migrations.
  • New indexes for knowledge-base lookups; case-insensitive email index skips itself if duplicates exist.
  • Monthly production computed per plant in Brisbane months.
  • Re-ingest embeds first, then swaps a document's chunks in one transaction; a failure keeps the old chunks.

Security

  • Login throttle: 8 failed attempts per email per 15 minutes, plus a per-IP limit.
  • Server-side masking of customer details for viewers; Drive/Gmail routes need ingest rights.
  • Password change revokes older sessions; 2 MB default body limit; baseline security headers.
  • Dependencies upgraded: @fastify/static 10, mammoth 1.13.

FFinal recommendation

Ready for production. Deploy these fixes with the steps below. The pending items are optional improvements and none of them blocks production.

  1. Commit the changes to development and push.
  2. On the droplet: discard the hand-copied edits, pull, npm ci, npm run build.
  3. Run npm run migrate (adds indexes, records the migration).
  4. Restart the app with pm2 restart tsba and check the site.
